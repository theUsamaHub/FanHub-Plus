# User-side video recording guide

## Script files and order

1. [Public visitor script](01-public-visitor-script.md): homepage, design reasoning, fandoms, content, characters, events, releases, merchandise, and support.
2. [Registered member script](02-registered-user-script.md): onboarding, personalised welcome, preference ordering, dashboard, collections, reviews, submissions, and settings.

Each page or feature has its own numbered section so you can record separate clips. Read only the narration; use the screen directions to plan clicks. Aim for roughly **9–11 minutes overall**, depending on speaking speed and pauses. The scope is the user experience, not the admin panel.

## Prepare before recording

- Start signed out, with the homepage ready and browser zoom at 100%.
- Prepare one working example each of an article, media item, character, event, release, and merchandise item. Select records with complete images and information.
- Use a fresh account for onboarding and the first-visit greeting. Onboarding currently requires three to five fandom selections; it is not a skippable step.
- Use an established example member account for populated history and collections if the new account has none. If switching accounts, briefly say: “I am now using an existing member account to show a populated dashboard.” The project README contains example login details.
- For the strongest personalisation demonstration, prepare content in both selected and unselected categories. Show a personalised listing with no restrictive filter applied.
- Prepare a short, relevant review and a sample submission in advance. Demonstrate real status messages without suggesting that pending content is already public.
- Check images, media playback, chatbot responses, and location discovery on the deployment you will record. Leave time for navigation and loading.
- Keep private information and passwords out of the recording. Use demonstration details in contact and feedback forms; submitting them sends real entries.

## Accuracy notes for the presenter

These scripts follow the current views, routes, and personalisation logic rather than older feature requests.

- Merchandise is currently a catalogue with bookmarks. Do not describe a cart, payment flow, prices, discounts, or stock controls that are not displayed.
- Event ticket buttons lead to an official external destination when provided. The Add to Calendar button is currently commented out in the detail view, so it is not part of this walkthrough.
- Personalisation prioritises favourite categories; it is not an AI recommendation model. Other categories remain eligible, but pagination and section limits mean they may not appear on the same screen. An explicit category filter can intentionally exclude other categories.
- Recommendations also use popularity and publication ordering. Continue Exploring reflects recently viewed stories; it is not a saved video playback position.
- The dashboard's upcoming-release summary count is a general count, not a claim that every release matches the member's preferences.
- The no-preferences fallback exists, but do not claim that a new user can skip the required onboarding selection. Demonstrate that fallback only with a suitable account that has no saved favourites.
- Public reviews require approval. Do not promise immediate public publication after submitting one.
- Nearby discovery depends on location access and suitable event data. Chatbot responses and outgoing emails depend on deployment configuration. If unavailable during recording, describe the interface briefly and continue without claiming a successful result.
- The design explanations are suggested presentation wording based on the interface. Adjust them to match your own original design intentions.

## Recording rhythm

Pause briefly after opening each page. Move the cursor only to the feature being explained, and avoid scrolling while reading an important sentence. Show one clear example of each action rather than repeating it on every content type. End on the dashboard or homepage so the final frame reinforces the project's identity.
